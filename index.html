TASK-4082 • PROD-DEFECT
Severity: Critical Priority: High Status: Verified

[Checkout] 500 Internal Server Error при применении промокода в корзине со скидкой 100%

Окружение: Staging v2.3.1 (Chrome 128, macOS 14.5 / Windows 11)
Компонент: Billing & Checkout Service / Cart API
Автор: Максим (QA Engineer)
Воспроизводимость: 100% (5/5 попыток)

1. Предусловия (Preconditions):

  1. Пользователь авторизован в системе под ролью `STANDARD_USER`.
  2. В корзину добавлен 1 товар стоимостью 1 500 RUB (ID: 98421).
  3. В базе данных активен промокод `FULLFREE` (скидка 100%, тип: fixed_percent).

2. Шаги воспроизведения (Steps to Reproduce):

  1. Перейти на страницу корзины: https://app.example.com/cart.
  2. В поле ввода промокода ввести: FULLFREE.
  3. Нажать кнопку «Применить».
  4. Нажать кнопку «Перейти к оформлению заказа».
✓ Ожидаемый результат (Expected):

Промокод успешно применен. Сумма заказа пересчитана до 0 RUB. Кнопка оплаты меняется на «Завершить оформление без оплаты». Заказ успешно создается с кодом 201 Created и статусом `FREE_ORDER`.

× Фактический результат (Actual):

После нажатия всплывает тост «Ошибка сервера». Запрос POST /api/v1/orders падает с кодом 500 Internal Server Error. В логах: PaymentGatewayException: Amount must be greater than zero. Пользователь заблокирован на шаге оформления.

SQL Query: Комплексная проверка заказа с JOIN по связанным таблицам 
-- 1. Проверка создания заказа, пользователя, статуса оплаты и связки с промокодом
SELECT 
    o.id AS order_id,
    o.status AS order_status,
    o.total_amount,
    u.email AS customer_email,
    p.code AS promo_applied,
    pay.status AS payment_status,
    pay.transaction_id
FROM orders o
INNER JOIN users u ON o.user_id = u.id
LEFT JOIN promo_codes p ON o.promo_id = p.id
LEFT JOIN payments pay ON pay.order_id = o.id
WHERE o.id = 'ord_98124'
ORDER BY o.created_at DESC;

-- 2. Проверка остатка товара на складе после успешного бронирования (Race Condition check)
SELECT product_id, stock_quantity, reserved_quantity
FROM warehouse_stocks
WHERE product_id = 'prod_4892';

Автотест сценария оформления заказа с применением скидочного промокода 100% (E2E Smoke)

Скрипт проверяет предотвращение регрессионного дефекта #TASK-4082: авторизация, добавление товара, применение промокода, перехват сетевого запроса API и проверка экрана успеха.

tests/e2e/checkout-promo.spec.js 
import { test, expect } from '@playwright/test';

test.describe('Checkout Flow & Promo Code Verification', () => {
  test('should successfully checkout with 100% discount promo code without 500 error', async ({ page }) => {
    // 1. Авторизация тестовым пользователем
    await page.goto('/login');
    await page.fill('input[name="email"]', 'qa_auto_user@example.com');
    await page.fill('input[name="password"]', 'StrongPass123!');
    await page.click('button[type="submit"]');
    await expect(page.locator('.user-avatar')).toBeVisible();

    // 2. Добавление тестового товара в корзину
    await page.goto('/catalog/item-98421');
    await page.click('button[data-testid="add-to-cart"]');
    await expect(page.locator('.cart-counter')).toHaveText('1');

    // 3. Переход в корзину и ввод промокода
    await page.goto('/cart');
    await page.fill('input[data-testid="promo-input"]', 'FULLFREE');
    await page.click('button[data-testid="apply-promo-btn"]');

    // 4. Ожидание успешного применения и пересчета суммы
    const totalAmount = page.locator('[data-testid="cart-total-amount"]');
    await expect(totalAmount).toHaveText('0.00 RUB');

    // 5. Перехват POST /api/v1/orders и верификация ответа сервера 201 Created
    const [response] = await Promise.all([
      page.waitForResponse(resp => resp.url().includes('/api/v1/orders') && resp.status() === 201),
      page.click('button[data-testid="submit-order-btn"]')
    ]);

    // 6. Проверка UI экрана успешного заказа
    await expect(page.locator('.order-success-title')).toContainText('Заказ успешно оформлен');
  });
});

Мой подход

03

Глубокое тестирование (UI + API + DB)

Прозрачные баг-репорты & Фидбек
